### M4 是这一轮唯一的真实发现（已修，`c18c0f1`）

旧的四条检查写成

```python
chk("sub_lo rounds OUTWARD (never above the exact difference)",
    sub_lo(mp.mpf(1)/3, mp.mpf(1)/7) <= mp.mpf(1)/3 - mp.mpf(1)/7)
```

右端 `mp.mpf(1)/3 - mp.mpf(1)/7` 本身就是**就近舍入**的 mpf 值，于是「朴素实现 `x - y`」会使左右两端**逐位相等**，`<=` 平凡成立——**这四条检查对它们要防的那个 bug 完全没有约束力**。（注意：被审的实现本身是**对的**（`sub_lo = LB(ivf(x) - ivf(y))`），这是**门的盲区**，不是证书的洞；但既然全节的论点就是「端到端外向舍入」，门必须能证伪它。）

修法：把四条检查改成**判别性**的——操作数选得让精确结果在 prec 103 下**不可表示**、且**就近舍入朝错误方向走**，参考值在 `mp.extraprec` 下计算（mpf 之间的比较跨精度是精确的），并**同时断言朴素实现会失败**：

| 组合子 | 操作数 | 精确结果 | 就近舍入给出 | 判别式 |
|---|---|---|---|---|
| `sub_lo` | 1, 2^-200 | 1 − 2^-200 | **1**（偏大，违反下界） | `sub_lo ≤ exact` 且 `(1−2^-200)_nearest > exact` |
| `add_hi` | 1, 2^-200 | 1 + 2^-200 | **1**（偏小，违反上界） | `add_hi ≥ exact` 且 naive `< exact` |
| `mul_hi` | (1+2^-100)² | 1+2^-99+2^-200（201 bit） | 1+2^-99（偏小） | `mul_hi ≥ exact` 且 naive `< exact` |
| `div_hi` | 1/3 | 1/3（不可表示，prec 103 处**向下**舍入） | 3·(1/3) < 1 | `3·div_hi(1,3) > 1` 且 `3·(1/3)_nearest < 1` |

（`div_hi` 这一条自身还踩了一个精度上下文坑：若把 `3*(1/3)` 放在 `mp.extraprec(20)` 内计算，`1/3` 会在 prec 123 下重算、乘 3 后又被舍回 123 位、恰好等于 1，断言假失败。已改为在基准精度下先取 `_third = 1/3`，再在 `extraprec(60)` 内做 `3*_third`（≤105 位，精确）。）

修复后重跑：M4 被 `sub_lo rounds OUTWARD` 精确捕获，其余 9 条结论不变。本机 `(0,3]` 全档 **1093 检查 / 71.7 s**（Stage A′ 635 + Stage S 23 + Stage L 435），16 粗节点 / 39 细胞，最小认证枢轴 5.19445e-8，承重细胞 [1.02246, 1.11523] pos/F = 0.5536——与修复前逐位相同（改的只是门，不是数学）。

### 乙.1 必修项 M-1（已修，见下）

**`iv.atan2` 不是外向舍入的** —— `tail_int` 的 `A>0` 分支因此不是「可证包含」，而 Stage L 的每个细胞都经它承重。

- 位置：原 `p4_cii_ci_interval.py` 中 `at = iv.atan2(A, x)`；下游 `S1_of` → `tail_sum` → `row_env`/`col_env` → `rsum`/`rsum_seg` → `schur_coupling`/`coupling_restricted` ⟹ `alpha_cell_iv`、`L1`、`N_ub`、`R3_ub`、`rtail`——即 Stage L 的 α、g_lo、E_hi、F_lo **全部**间接依赖。Stage S 不受影响（`A=0` 分支是初等的 π/2 常数，但那时用的是 `iv.pi`，同样被一并替换）。
- 原因（mpmath 源码 `libmp/libelefun.py`）：`mpf_atan2` 先算 `mpf_atan(mpf_div(y, x, prec+4), prec+4)`（**就近舍入**），只在最后一步 `mpf_pos(tquo, prec, rnd)` 施加方向舍入。方向舍入作用在一个已带 ±2^-(prec+4) 误差的中间值上，**不保证包含**。
- reviewer 的复现：20 万对随机点区间操作数与 600 bit 参考比较，**9.3–9.4% 的结果不包含真值**，最坏违规 0.235 ulp@prec103；生产操作数类（A 为 [0.3125,45] 内 2^-16 倍数、x 为 1..3000 整数）60000 次中 5735 次不包含；**传到 `tail_int`** 后 20000 次中 14 次不包含，最坏相对 6.2e-30。
- 为什么算洞：模块 docstring (a) 与 §2.A.1 第 1 条的核心论点就是「每个初等运算返回一个**可证**包含精确实数结果的区间」。这条对 `atan2` 不成立；它恰恰是本节声称消灭的「未量化舍入假设」的同类。

**修法（已实施）**：不用「高精度算完再加垫」（那正是本文件要去掉的东西），而是从零写一个只用 `+ − × ÷ √` 与整数幂的**认证反正切** `iv_atan_nn`：

1. 反复用 `atan(t) = 2·atan(t/(1+√(1+t²)))` 把参数减半（`ATAN_HALVINGS = 80` 上限）直到 `UB(u) ≤ 2^-4`；
2. 对交错级数 `Σ (−1)^j u^(2j+1)/(2j+1)` 取 `ATAN_TERMS = 20` 项，余项用**交错级数余项定理**给出对称区间 `±UB(u^41/41)`；
3. 乘回 `2^m`。`iv_pi_half() = 2·iv_atan_nn(1)`。

`tail_int` 的 `x=0` 分支改用 `iv_pi_half()`、`A>0` 分支改用 `iv_atan_nn(A/x)`（原 `iv.atan2(A,x)`，同值）。验证：3000 个操作数对 600 bit 参考 **0 次不包含**（同一测试下 `iv.atan2` 为 200/3000），相对宽度 6.3e-30，π/2 相对宽度 4.5e-30；2000 次 `tail_int` 调用 0.35 s（性能无退化）。

门里同时加了 **4 条严格自洽恒等式 + 2 条证据检查**：`atan t + atan(1/t) = π/2`（6 个数量级尺度）、倍角 `atan(2t/(1−t²)) = 2 atan t`（3 个）、Machin `π = 16 atan(1/5) − 4 atan(1/239)`、区间宽度 ≤ 1e-27 相对、以及 240 个操作数对 600 bit 参考的包含性。前四类是**严格**的（只用 `iv_atan_nn` 自己，不引用任何外部高精度值），足以钉死减半次数、项数与余项常数。

   - 另加 3 × 2 条：`alpha_cell_iv` 里**唯一未被其它检查触及的那一步**是 Weyl/Lipschitz 覆盖 `λ₂(head(w)) ≤ max(c_A,c_B) + L₁·(B−A)/2`。现在在细胞中点再跑一次头块区间 Cholesky（Na=70/140，0.2–1 s），直接验证该不等式。它对 L₁·hw 项的余量约 10³ 倍（L₁ 界 ‖∂_ϖℌ‖ ~ O(1)，λ₂ 随 ϖ 变化极慢），但**恰好能捕获它要防的那个 bug**——把 Lipschitz 项整个删掉：实测 c(中点) = 4.327671e−5 **>** c(端点) = 3.600594e−5，于是不等式立刻破。
7. 超越基元的包含性 —— 「本次唯一真正失守的一项」。→ **已修**（M-1）+ **源码级回归闸**：Stage A′ 用 `tokenize` 解析本文件自身（因此注释与 docstring 里的散文既不会误报也不会掩盖），断言 **Secs 0–6（一切产生界的代码）里不出现任何 `mp.`/`iv.` 超越函数调用**——白名单只有 `iv.sqrt`（mpmath 的 `mpi_sqrt` 对两个端点分别调用 `mpf_sqrt(·, prec, round_floor/round_ceiling)`，方向舍入直接作用在开方本身，这与 `mpf_atan2` 正相反），且只经 `iv_sqrt_nn` 到达；`mp.sqrt`（就近舍入）照样禁止。这条闸的**牙齿已验证**：把 `_ = iv.pi + iv.atan2(...)` 注入 SEC.3，门立刻以 `iv.pi@684; iv.atan2@684` 失败。

## 丁. 交叉审查：把别处发现的失效模式拿来查自己

段 C-I 的区间化过程中发现的 `iv.atan2` 缺陷被通报给第 2-a 层后，那边独立复现了它，并**又发现一处包含失效，而且是在我们自己的代码里，不是库里**。协调层要求我拿这两条回头查本模块。以下是逐条结论（**把否定的结论也明确写出来**，不要让读者去推断）。

### 丁.1 `iv.atan2` 不是外向舍入的（本层首先发现）

机理与实测见 §乙.1。**通则**（协调层要写进论文的可复现性节）：**用了区间库不等于每一步都在做包含**；每一个超越基元都必须对高精度参考单独审计，并用**源码级闸**强制「只许 `+ − × ÷ √` 与整数幂」。

对 mpmath 1.3.0 四个基元的审计（本层与 2-a 各自独立做，结论一致）：

| 基元 | 判定 | 证据 |
|---|---|---|
| `iv.atan2` | **不健全** | 本层 9.4%/200000 不包含，最坏 0.24 ulp@prec103；传到 `tail_int` 后 14/20000，最坏相对 6.2e−30。2-a 独立复现 2502/40000 随机 + 1429/20000 系统，最坏 1.41e−32 |
| `iv.sqrt` | 健全（**构造上**） | `mpi_sqrt` 对两端点分别调 `mpf_sqrt(a, prec, round_floor)` / `mpf_sqrt(b, prec, round_ceiling)`——方向舍入直接作用在**开方本身**。本层 0/40300，2-a 0/40000 |
| `iv.log` | 健全 | 2-a 0/120000 |
| `iv.pi` | 健全 | 端点与定向的 `libmp.mpf_pi` 逐位相同 |

本模块的处置：`iv.atan2` 已彻底移除（换成自造的 `iv_atan_nn`/`iv_pi_half`）；`iv.log`/`iv.pi` 本来就没用，**即使现在已知它们健全也不放回**——没有理由去扩大被信任的基元集合，本模块有认证替代品。

### 丁.2 唯一还被信任的库基元，只有 `iv.sqrt`

说白一点：**`iv.sqrt` 是承重路径上最后一个仍然信任 mpmath 库实现的基元。** 它不是被证明的，是被（很强的）证据支持的：

- **构造性理由**（比证据更重要）：源码里方向舍入施加在开方结果上，而不是像 `mpf_atan2` 那样施加在一个已带 ±2^-(prec+4) 误差的中间值上。这是结构性的区别，也是为什么两者结论相反。
- **证据**：本层 40300 个操作数（300 个横跨 13 个十进量级 + 40000 个分三种形状：随机 13 量级、贴近 1、`1+s²` 且 s ∈ [0,300]）对 600 bit 参考 **0 次不包含**；2-a 独立地 0/40000。
- **参考构造经得起「`mp.pi` 惰性常数」那个坑的检验**（协调层专门要求反向核查，怕的是参考恰好匹配而给出**假全清**）：参考是 `with mp.workprec(600): mp.sqrt(t)`，返回的是一个**已物化**的 mpf（实测尾数 599 bit，且在环境精度 53 与 800 下打印出**相同**数字）；操作数由 `mp.mpf(i)/7 * mp.mpf(10)**k` 构造，**全程不出现任何惰性常数**；比较在环境精度下进行，但 mpf↔mpf 比较跨精度是**精确**的。故本层的 `iv.sqrt` 结论**不受该坑影响**。
- **而且这个检验是判别性的**（否则 0 次不包含毫无意义）：门里现在同时断言「一个**就近舍入**的点值 `sqrt`（即 `iv.atan2` 那一类缺陷）在同一组操作数上**会**错过同一个参考」——实测 296/300。对 `iv_atan_nn` 那条证据检查也加了同型的判别断言，反面对照直接用 `iv.atan2` 本身（这是 `iv.atan2` 在本文件里**唯一**还被求值的地方，只在 Sec.7、只作反面对照，绝不作界）。这一课来自本轮更早的一个真实 bug：四条单边舍入检查曾因为参考自身是就近舍入的而**平凡成立**（§甲 M4）。

想彻底消除这一条，需要把 `iv.sqrt` 也换成 Newton 迭代 + 区间验证。**本节没有做**，并在 §2.A.5 第 2 条里明说。

### 丁.3 float64 出现在哪里，以及为什么那些位置不可能是界

同样说白一点。float64 在本模块只出现在**三个**位置，没有一个是界：

1. **试探向量 v̂ 与头块紧缩向量 u**。这不是「精度够用」的论证，而是**根本不需要精度**的论证：对**任何**固定单位向量 v，Rayleigh 商 ⟨v, ℌv⟩ 就是 λ₁(ℌ) 的一个**合法下界**——v 越差，界越松，但**永远合法**。同理对**任何**单位向量 u 与 P = I − uuᵗ，有 `λ₂(A) ≤ λ_max(PAP)`（因为 λ₂ 是「在某个一维子空间的正交补上取 max」的最小值，取 S = span{u} 就得到一个上界），故 u 只影响紧度。两者的 float64 分量按其**本来的精确二进制有理数**进入 `ivf(float(t))`，归一化在 `iv` 内完成。**一个 f64 特征向量不可能让这里出假阳性，因为它根本没进入不等式的合法性。**
2. **选取参数**（粗步长、细分次数、Ns/Na、Cholesky 位移 c 的种子）。它们决定「认证哪些不等式」，不决定「它们是否成立」。位移 c 尤其值得说清：c 是被**区间 Cholesky** 认证的那个量，种子取错只会让升级循环多跑几轮或失败，**不会让它假通过**。
3. **Stage A′ 里的全部 `np.*` / `mp.quad` / `mp.zeta`**，显式标注为**证据**，并被 §乙.4 第 7 条那道源码级闸挡在 Secs 0–6 之外。

此外（本轮自查新加的一条）：**判定链上不许有窄类型**。`cell_L_iv`/`cell_S_iv` 返回的 `hpp_ub` 是 mpf；阶梯的接受判据 `ub >= 0` 一直是 mpf 判定，但 Stage L 的那条断言此前写成 `float(hpp_ub) < 0`。实际上不可能出错（每个认证细胞 |hpp_ub| > 1，float 化改变符号需要下溢到 −0.0，即 |x| < 2^-1074），但既然本节的论点就是「判定不依赖未量化的浮点」，已改为 mpf 布尔 `info["hpp_neg"]`，并加了一条断言两者同号的检查。

### 丁.4 2-a 的 `theta_star_iv`：垫取自二分宽度——本模块有没有同型问题？

2-a 的发现（`p4_cii_m3_interval.py:652-655`）：`margin = float(b - a)` 取的是**二分区间宽度** ≈ 2.3e−41，而同一函数里 `v = float(val)` 引入的 float64 误差 ≈ 5e−17，于是返回的区间以 **4.8e−17 在不安全方向**错过真 Θ*。这类缺陷**自我遮蔽**：内层收敛越好 ⟹ 垫越小 ⟹ 失效越严重。通则：**垫必须覆盖它所代表的那个误差源**；任何「高精度算完、返回窄类型」的路径至少要留一个**窄类型**的 ulp，绝不能拿高精度侧的量当垫。

本模块的自查结论：

- **没有垫**。`PAD = mp.zero`，且门里断言其为零（变异 M3 即由它捕获）。所以「垫的来源不对」这个经典形态在本模块**不存在**。
- **但协调层提醒这个模式也藏在「升级逻辑」里，这一点值得认真查，而且确实查出了东西可说**。本模块认证路径上有三处循环，逐个过：
  1. **`lam2_head_iv` 的 Cholesky 升级循环**（c 按 `CHOL_GROW = 4` 倍增直到区间 Cholesky 成功）。合法性完全来自 `chol_pd`，与循环跑了几轮无关；`CHOL_C0 = 1e-12` 与 `×1.000001` 只调整**种子**，而把 c 调大只会让结论**更弱但仍然合法**（c 是 λ₂ 的上界）。**不是垫。**
  2. **`iv_atan_nn` 的减半循环**。退出条件 `UB(u) ≤ 2^-4` 被 `assert` 强制；余项**不是**从这个阈值估出来的，而是循环结束后从区间量 `tp = u^(2N+1)` 用 `UB` 塌缩得到的——即误差界来自**它要覆盖的那个算术本身**，正是 2-a 那条通则要求的方向。上限 `ATAN_HALVINGS = 80` 用完则 `assert` 失败，**没有静默退路**。
  3. **`cell_L_iv` 的 (V1)–(V3) 自洽角迭代**——这是本模块**唯一**形状上像 `theta_star_iv` 的地方，所以查得最细。结论：合法性**不依赖收敛**（起点用先验界 E ≤ N_ub；映射单调递增，故「σ ≤ s ⟹ σ ≤ Φ(s)」，每个迭代值独立合法），退出判据 `s_new >= s` 只决定**何时停止改进**，从不被转成误差估计。
- **精确的边界陈述，不夸大**：为了检验上一条，我把迭代上限 `DK_ITERS` 依次设成 0,1,2,3,6,12,24 在同一细胞上重跑。扫描结果（[1.0, 1.125]，用 mpf 基线输入）：

  | 上限 | 0 | 1 | 2 | 3 | 6 | 12 | 24 |
  |---|---|---|---|---|---|---|---|
  | `hpp_ub` | **+0.3478** | +0.0760 | +0.00654 | −0.01380 | −0.022658 | −0.0229448 | −0.0229451 |

  所以**必须承认**：这个迭代对「证书是否**闭合**」是**承重的**（上限 0 时根本闭不上），我原先想断言的「上限取 0 也照样闭合」是**错的，已删**。它不承重的是「已闭合的证书是否**合法**」。**这正是与 `theta_star_iv` 的结构差别**：那里截断迭代会让包含**变错**（宣称一个并不成立的界）；这里截断只会让细胞**失败闭合**（`ub >= 0` ⟹ `bad = True` ⟹ 继续二分），即 **fail closed**——欠收敛能拖慢甚至卡死阶梯，不能制造假阳性。门里现在直接检验这三条（§2.A.3 (l)）：每个上限都返回界、`hpp_ub` 随上限单调不增、上限 0 时**返回正值而被拒绝**。顺带量出一个诚实的小账：压缩比 ≈ 0.32，12 轮**还没有**完全收敛，12 与 24 相差 1.3e−5 相对（24 更紧），故生产常数 `DK_ITERS = 12` 确实留了一点锐度在桌上，但在**安全侧**，不值得为此作废已跑完的生产日志。
- **本模块不 import M3**，因此 M3 的 `atan_iv`/`theta_star_iv` 污染不会传入。头块是在 `iv` 内由核表直接构造（`head_iv`），门里与 f64 `op_np` 对拍确认（Na = 6, 30；ϖ = 0.3125, 3, 44，差 ≤ 2.2e−16），**不是 f64 拷贝**。Stage S 的 𝔤(2) 也是自足的：`lamhat_lo = LB(tr.qform(fG2))`，一个在 `iv` 内算出的 Rayleigh 下界，**不引用** §4.1 的 𝔤(2) 夹逼（那一条已由第 1 层解析关闭，`P4_g2_analytic.md` v1.1 / `d163ae4`）。

### 丁.6 对自造 `iv_atan_nn` 做变异测试：发现一个真实盲区（齐次性）

2-a 的收尾提醒是：**「凡是参考与被测对象出自同一条代码路径的检查，都值得拿一个故意写坏的实现重跑一遍，确认它会失败。」** 我那四条反正切自洽恒等式正是这个形状——除了两条 600 bit 参考证据外，它们只拿 `iv_atan_nn` 和它自己比。于是把 `iv_atan_nn` 参数化，逐个注入缺陷，**每次在独立子进程里跑真正的门**（不是恒等式块的副本），记录是哪一条检查报的警（`chk` 首 failure 即抛，故失败名唯一）。探针 `theory/notes/_scratch_ir/mutate_atan2.py`（未提交）。

| 只取 4 项但保留余项（合法，只是更宽） | 过恒等式、挂宽度检查 | 宽度检查 |

**真实盲区（这是本轮变异测试的主要收获，不是走过场）**：三条恒等式（互余角、倍角、Machin）都是 atan 的**一次齐次式**，而 `iv_pi_half` 本身也由 `iv_atan_nn` 构造——于是**整套恒等式在 atan → C·atan 下不变**，**结构上看不见倒缩因子写错**。实测证实：`2**(m±1)` 这类把结果整体缩放的变异，三条恒等式**全过**，唯一报警的是 600 bit 参考证据检查。那是**强度不对**的检查：一个粗到 100% 的错误，不该只由「证据级」的东西兜住；何况本模块对外的说法是「恒等式是严格的、参考只是证据」。

**第 2-a 层独立复现了这一条**：把同一实验做到 M5 自己的反正切上（每个变异一个 fork 子进程，并从变异体重建 `PI_IV`，否则 Machin 会因为「π 还是原版造的」而以**错误的理由**报警），`2^(k+1)` 与 `2^(k−1)` 两个方向都**只被 `mp.atan` 700 bit 参考检查捕获**，三条恒等式无一报警。两份**互相独立**的实现给出同一结论，排除了「某个代码库的偶然」。

**修法**（已合入，门 880 → 883 → 888）：加一条只用**有理算术**的**绝对锚**。对 0 < u < 1，反正切交错级数的项严格递减，故相邻部分和**夹住**真值：

  u − u³/3 < atan u < u − u³/3 + u⁵/5，

对 u = p/q 两端都是分子分母显式的精确有理数（lo = (3pq²−p³)/(3q³)，hi = (5q²·(3pq²−p³)+3p⁵)/(15q⁵)）；而认证区间的端点是精确二进小数（直接从 `_mpf_` 读出 sgn·man·2^exp，是**数据**不是计算），于是**比较在 Python 整数里精确完成**——不含任何超越函数、库基元或高精度参考，**不等式两侧都没有浮点**。（第一版把 lo/hi 写成 mpf 表达式 `u - u**3/3`，那其实是**舍入过的**：1/24 不是二进小数。差距 u⁵/5 比 2^−103 大二十多个量级，所以结论不受影响，但既然本节通篇的论点就是「严格 vs 证据」，就不该在这里留一个口头的「精确有理数」。）

**锚点取 u = 9/10, 1/2, 1/4, 1/8**，刻意让减半循环分别跑 **4 / 3 / 2 / 1** 次——这是 2-a 的加固建议：只钉一个深度的话，「浅层倒缩对、深层倒缩错」的变异能活下来；四点全扫不到 1 ms。u ≤ 0.9 是因为夹逼要求各项严格递减（需 u < 1），且 u→1 时夹逼迅速变宽（u = 0.9 宽 0.118，u = 1/8 宽 6.1e−6），但即便最宽的那一点也比要抓的「2 倍」误差紧四个量级。另加 4 条**反面对照**，断言这些锚对**两个方向**的倒缩变异都确实报警（把结果乘 2 会越过 hi，除以 2 会掉到 lo 之下）——否则新检查自己也可能是平凡的。

**诚实的局限**：「20 项但完全丢掉余项」抓不到，而且**抓不到是对的**。20 项在 u ≤ 1/16 时的余项约 2^−164，远在 prec 103 的一个 ulp 之下，区间端点**逐位不变**，任何在 prec 103 下运行的检查都不可能分辨。2-a 在 M5 上用 **Horner** 求和（我是前向累加）得到**同一结论**——不同的求和次序给出同样的不可见性，说明这不是某一种舍入模式的巧合；其项数扫描（t=1）为 5.93e−12（N=4）、1.06e−22（N=8），**N=12 起平台在 1.775e−30**，即余项从 N=12 开始就不再是瓶颈，之后全是累积舍入。要覆盖这一档只能提高工作精度重跑，但那检验的是「余项项数够不够」，而余项在**代码里确实加了**，且其大小来自它所覆盖的那段算术本身（后循环的 `tp = u^41` 经 `UB` 塌缩），不是从阈值反推的估计。故此档留空是**已知且可解释**的，不是漏洞。

**方法学附注（给后来做多变异测试的人）**：探针一度报出某些变异只有 875 条检查而基线 880，我一度怀疑**检查数依赖输入**——那会让门的计数作为文档指纹失效。用 `countdiff.py` 逐条 diff 检查名后确认：少掉的 5 条全在 `stage_S_setup` 里，该函数以 `if "tr" in SDATA: return SDATA` 记忆化，**在同一进程里第二次调用 `run_gate` 就会跳过它们**。即这是**探针自身的产物**，不是输入依赖。教训：**在同一进程里连续跑多个变异时，任何模块级缓存都会污染计数**；现在的探针改成**每个变异 fork 一个子进程**（2-a 采纳了同一做法，并额外指出还要从变异体重建派生常数，否则报警理由会是错的）。
