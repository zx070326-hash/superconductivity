## 1. ⛔ certificate-upgrade：脚本不声音，**禁止上 petlove 跑**

`_scratch_ir/h3s_deficit_cert_production.py` 有两处独立缺陷，任一单独就足以让
「certificate」名不副实。

### (a) 算子本身写错：L1 差一项（承重，改 Tc 11%）

KAY 定义 L1_n = (1/(2n+1)) Σ_{k=1}^{n} 2f(k)。脚本两处（`build_O_matrix_pt` 的
`fker[1:n]`、`build_O_matrix_iv` 的 `range(1, n)`）都只加到 k=n−1，**漏掉 k=n 项**。

- 直接比对（f(k)=1/(1+k)，n=20）：KAY 0.1290418880 vs 脚本 0.1267190077，**相对差 1.8%**。
- 传到 Tc（H3S-200 anharm，N=400，float64 复现脚本的 L1）：

  | | Tc(μ*=0) | Tc(μ*=0.13) |
  |---|---|---|
  | 基线（KAY） | 283.344 K | **198.974 K** |
  | 证书脚本的 L1 | 307.856 K | **221.134 K** |

  **+11.1%。** 比预算里任何一项亏损的不确定度都大。
- 危险性在于：pt 版与 iv 版**错得一致**，所以脚本内部的自洽检查一定通过，
  区间宽度照样报 ~1e-49。这就是「把假命题装进漂亮区间」的教科书样例。

### (b) Rayleigh 商不是特征值的外包（方向违规）

`rayleigh_interval(A_iv, V_pt[:,k])` 用 **float64 近似特征向量** 的 Rayleigh 商当作
μ_k 的区间，然后把整串 `ev_iv` 喂进久期方程。但：

- 对**最大**特征值，R(v) ≤ μ₁ 恒成立 —— 只给**下界**，永不给上界；
- 对**中间**特征值，R(v) 与 μ_k 的大小关系**无定论**（数值演示：eigh 误差 ε=1e-5 时
  R−μ 在 −6.5e-8 与 +6.6e-8 之间两侧乱窜）。

所以 `ev_iv` 根本不是谱的包含，久期根也就不是 λ₁ 的包含。区间算术只外包了
「给定 v 的 Rayleigh 商」这个量的**舍入**，没有外包**特征向量误差**——正是
`quadrature-bias-not-caught-by-dps-agreement` 那条教训的同构翻版。

> 正确做法（留给重建）：要 λ₁ 的**上界**必须另找机制——Gershgorin / Kato–Temple
> （需残差范数 ‖Av−R v‖ 的区间界）/ 或对整个区间矩阵做外包谱界。
> 按**单边界方向规则**：λ₁ 的下界只能给出 Tc 的下界（PASS 方向），
> 要 Tc 的上端点必须有 λ₁ 的真上界。现脚本两端都当成立。

次要项：`Nc = floor((r·ϖ)的下端点)` 是单边的（Nc 偏小 ⟹ 库仑偏弱 ⟹ Tc 偏高），
只支持 Tc 上界，不支持下界；重建时两端要分别取。

### (c) 「λ reldiff = 2.43e-05 与 float64 基线不符」——是假警报，但验证本身是空的

agent 同时声称 λ 被认证到区间宽 ~7e-49 **且**与 float64 基线差 2.43e-05（自相矛盾）。
我从零重算耦合常数 λ = 2∫α²F/ω dω（H3S-200 anharm，500 点文件网格）：

- agent 认证值 1.7209582177 —— 与真值一致到 ~1e-11 ✔

2.43e-05 的来源：`1.7210`（我笔记里**四位显示舍入**的那个数）对 1.7209582 的相对差
正是 2.4e-5。agent 拿显示值当基线对比了。**λ 的数字没问题，但那句「已对 float64
基线验证」验证的是舍入显示，等于没验。** 这条不影响 (a)(b) 的判决。

agent 报：作者 Tc = 209.7 / 164.8 / 221.4 / 170.0 K，我们系统偏低 **−3.0%（std 0.1%）**。
