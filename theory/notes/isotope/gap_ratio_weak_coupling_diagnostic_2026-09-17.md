# Gap ratio 弱耦合诊断（2Δ₀/k_BTc）——BLOCKING 裁定

日期 2026-09-17。任务来源：team-lead 指派，检验 gapratio 在 λ=0.5, μ*=0 下报告
2Δ₀/k_BTc=4.05（对比 BCS 3.53，判 +15% BLOCKING）这一结论。主会话此前提出假说：
3.53 是 λ→0 极限而非 λ=0.5 的参考值，正确参考应是 Carbotte 强耦合公式给出的
3.7042，故 +9.4% 是"物理"。本笔记独立复核，**结论与两边猜测都不同**：真正的
主导误差源是 gapratio 自己代码里的 **Matsubara 截断数 N 与温度/耦合强度脱钩**
的 bug，其量级足以解释全部残差，不需要诉诸任何新物理。

## 1. 代码路径核查（analytic，读源码）

`theory/solvers/eliashberg_iso.py::Solver.solve_gap` 返回 `(wn, delta, z, conv)`，
`delta` 是虚轴 Matsubara 格点 ω_n=πT(2n+1) 上的 Δ_n 数组，`delta[0]` 就是
**Δ(iω₀)=Δ(iπT)**——纯虚轴量。全仓库搜索
`gap_ratio_diagnostic.py` / `_full_analysis.py` / `_h3s.py` / `_key_findings.py`
四份脚本，无一处做实轴解析延拓（Padé 或其他），全部直接把 `delta[0]` 当作
BCS 意义下的实轴能隙边 Δ₀ 使用（例如 `gap_ratio_key_findings.py` 第 44 行
`delta0 = delta[0]`）。

**查证结果**：gapratio 确实把 Δ(iω₀) 当成了 Δ₀（主会话任务 2 的假说方向正确），
但下面第 2 节显示这个概念混淆不是本例中数值残差的主要来源——真正的主导效应
是更粗暴的截断误差。

## 2. 真正的主导 bug：n_matsubara 与 T、λ 脱钩（numerical-evidence，独立重建）

`Solver.__post_init__`/`_n_for_T` 本身有一个自动定 N 的安全机制：
`N ≈ oversample·w_cut/(2πT) + margin`，确保 Matsubara 网格能覆盖到 `w_cut`。
但四份 gapratio 脚本全部**手动传入固定 `n_matsubara=400`**（H3S 脚本用 600），
绕开了这个自动估计。低温、弱耦合时 Matsubara 间距 2πT 远小于强耦合情形，
固定 N=400 覆盖不到 `w_cut=500 meV`。

用 `Solver._n_for_T` 自己的估计公式核算，在 gapratio 用的
`t_low=0.02·Tc`（`gap_ratio_diagnostic.py` 用的正是这个比例）下，覆盖
`w_cut=500 meV` 所需的 N：

| λ | Tc (K, μ*=0) | t_low=0.02·Tc 处 Matsubara 间距 (meV) | 覆盖 w_cut=500meV 所需 N | gapratio 实际用的 N |
|---|---|---|---|---|
| 0.5 | 22.88 | 0.2479 | **2017**（auto 估计给 6081，含 oversample=3 与安全边际） | 400 |
| 0.3 | 5.767 | 0.0625（推算） | **8006** | 400 |
| 0.2 | 1.060–1.10 | ~0.011 | 自动估计给 **N=24064**，触发求解器自带的 `RuntimeError`（N 超过 O(N³) 安全上限 20000） | 400 |

即 gapratio 在 λ=0.5 处只用了所需 N 的约 1/5–1/15，λ=0.3 处约 1/20，
λ=0.2 处所需 N 已超出求解器自身设定的安全上限——这个区域用固定 N=400 稠密
本征分解**根本不可能收敛**。

### N 收敛性实测（独立重跑，逐字复用 gapratio 的算子/参数：ω_E=50 meV,
μ*=0, w_cut=500 meV, t_low=0.02·Tc, mixing=0.2, max_iter=3000）

λ=0.5（`_chk_gapratio_weak_coupling_Nconv.py` + `_chk_lam05_N3200.py`）：

|---|---|---|---|
| 400 | 22.880 | 4.391 | 4.454 |

| 1600 | 22.878 | 3.647 | 3.700 |
| 3200 | 22.878 | 3.601 | 3.653 |

Tc 本身在 N=400 就已收敛（400→3200 只变化 0.001%），但 **比值随 N 单调下降、
远未收敛**，连续差分 0.574→0.180→0.047，公比≈0.28–0.31，几何外推
N→∞ 极限 ≈ **3.63–3.64**（这一步是我自己做的几何级数外推，**不是** certificate，
只是 numerical-evidence 级的估计，标注清楚不确保严格）。

λ=0.3、λ=0.2（同一脚本）：

|---|---|---|---|

这两组**非单调、无收敛迹象**——λ=0.2 甚至从 1.33 一路窜到 4.28，纯粹是欠采样
噪声（该 λ 下真正需要的 N 超出求解器安全上限，N=400/800/1600 全部远低于所需
的 ~24000，这些数字不代表任何收敛极限，不能读出物理结论）。

**这直接推翻团队消息里"λ=0.2 若收敛到 3.53 则方法健全"的检验设计前提**：
在 gapratio 的固定 N=400 方法论下，λ=0.2 根本不会给出任何有意义的收敛值——
既不会收敛到 3.53，也不会收敛到别的数，因为 N 远未进入渐近区间。所以"λ=0.2
测试"本身对健全性没有诊断力，除非同时把 N 提到所需量级（这在 λ=0.2 处已经
撞到求解器自身的 O(N³) 安全阀）。

## 3. 结论与裁定

**BLOCKING 应当撤销**，但理由与团队消息里给出的两种猜测（"方法健全，+9.4%
是物理"）都不完全对：

- gapratio 报告的 4.05（λ=0.5, μ*=0）**主要是数值截断误差**：其 N=400 只覆盖
  了所需 Matsubara 窗口的 ~1/5–1/15，真值（外推 N→∞）约 **3.63–3.64**，
  比报告值低 ~10–11%。
- 主会话提出的 Carbotte 参考 3.7042 与外推真值 3.63–3.64 相差 ~2–3%——这个
  量级与 Carbotte 公式本身作为 O((Tc/ωlog)²) 展开式的近似误差同量级，**不需要
  额外物理机制**来解释；不能确证"物理上多出 9.4%"，因为原始 4.05 本身就是
  被截断误差污染的数字，不能直接拿来算偏差。
- Δ(iω₀) vs 实轴 Δ₀ 的概念混淆（任务 2）**确实存在**（查证见第 1 节），但在
  λ=0.5 这个例子里，它造成的偏差被截断误差完全掩盖，无法从现有数据里单独
  分离出它的贡献量级；只能说这是 gapratio 方法论里另一个独立的、方向未知的
  系统偏差来源，需要在 N 收敛之后单独评估（例如做 Matsubara→实轴 Padé 延拓
  再比较）。
- gapratio 的原始 BLOCKING 论断（"BCS 极限检验失败，说明方法有 bug"）**方向
  是对的**——确实有 bug——但**诊断错了 bug 的位置**：它从未指出是 N 截断，
  而是把矛头指向"强耦合修正/BCS 参考值选取"，这个归因不成立（第 2 节的 N
  收敛测试已经排除了"方法在恰当 N 下健全，只是参考点选错"这一可能性——即使
  换上 Carbotte 正确参考，λ=0.5 处 N=400 的原始数字仍然因截断误差偏高
  ~10%，这个残差不会因为换参考值而消失）。

**建议**：gapratio 若要继续用这条 Matsubara 直接求解管线算 2Δ/kTc，必须
（a）用求解器自带的 `n_matsubara=None` 自动估计而非手动固定 N，或至少对每个
(λ, w_cut, T) 组合做 N 收敛扫描；（b）在极弱耦合（本例 λ≲0.3 且 w_cut/ωlog 較大）
区域，稠密 O(N³) 直接对角化会撞到 N 的实际计算上限，需要换算法（例如折叠/
Toeplitz 结构的迭代法，类似 `_chk_gapratio_bcs_reference.py` 里用的 dimensionless
算子）；（c）Δ(iω₀) vs Δ₀ 的概念问题独立存在，修好 N 之后仍需处理。

## 4. 严格性分级

- 第 1 节（代码路径核查、delta[0] 定义）：**analytic**（直接读源码，无计算）。
- 第 2 节 N 需求表：**numerical-evidence**（float64，`Solver._n_for_T` 公式代入 +
  一次 `RuntimeError` 触发确认）。
