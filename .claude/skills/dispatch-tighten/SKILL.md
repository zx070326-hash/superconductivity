---
name: dispatch-tighten
description: 派活，且交付物会被某个判决直接消费（收紧/认证/复核一个承重量）。产出一份 6 格 prompt。填不出预算或消费点 ⟹ 不派。
---

用户原话（`$ARGUMENTS`）**原样**作为 prompt 首段，不改写、不翻译、不补全；模型/agent 类型按用户指定，作为 Agent 工具参数传，不写进正文。

prompt 正文 = 下列 6 格，逐格填实；任何一格填不出 ⟹ 不 spawn，回头补或退回用户：

1. **目标**：一句可证伪的话「测定/判定 X，判据是 Y」+ 要求档位（analytic / rational-exact 含格数与有理数个数、不得简称 analytic / certificate / numerical-evidence）。
2. **预算**：把该量朝**判据变难**的方向退化（×κ≥1 / 取 ∞ / 从链条删掉），下游判决在哪翻转。**∞ ⟹ 不派**。含目标常数时加一行：所选估计子在 float64 上的固有松 ___ < 目标 ___？
3. **消费点**：这个数在哪一格 / 哪个不等式里被用掉。
4. **验收门**：执行方开工前必须先复现的已知数（值 + 出处 + 容差写 `x ± tol·|x|` + 约定）。
5. **约定钉死**：单位（meV/K 混用须写 k_B）、ω_c 约定、归一方式（乘性/加法）、谱 / N / T_low / μ*。逐项写，不写「按仓库惯例」。
6. **证据不对称**：相合能得出 ___；不合能得出 ___。单边界只产出「过」。

先验检索由 hook 自动追加到 prompt 末尾（lead 与执行方各看一份），**不要手抄**；但派出前读一遍命中的非 live 文件。hook 没附加时手动跑 `sh tools/prior_art.sh "<承重量>"`。
多方向并行：每个方向各过一遍本 skill，另加一行「各方向共享的文件/结论：___」——非空则不是并行，是串行。
执行方纪律不写进 prompt：子 agent 已加载 CLAUDE.md（2026-09-20 实测）。
