对每份交付（`$ARGUMENTS` = 交付摘要或 agent 名）逐项做，不是逐项读：

1. **先 grep 仓库**：这个结果是否三天前就在（ASCII slug 检索）。已在 ⟹ 它是二次验证，不是新工作，按此记账。
2. **复核对象是脚本/文件本身**，不是消息里的转述。承重数字自己从零重算；它的「已完成」是线索。
3. **数自由度**：它报的「闭合/自洽 PASS」，判据显式写出后有几个印出量相消？加法闭合 = 恒等式。
4. **未索引笔记**：`git status` 看它新建的 `.md`，逐个查 INDEX.md；被它自己后一次交付取代的，旧行写 `superseded by <文件名>`。
5. **多份交付互引**：A 引 B 的结论不算 A 的证据；三份同向 ≠ 三次独立（共因：同一 spec、同一数据源）。
6. **快照过期**：交付所依据的笔记版本，是否早于一次相关撤回。是 ⟹ 结论作废，不唤醒该 agent，重开。
7. **它报「某界收紧 / 某判决翻转」**：先测 N 收敛分清「数字错」还是「证书松」（后果相反）；翻转量换算回本来的成本单位（格数，不是比值）；为旧界解过的下游优化必须重解。
8. 采信的每个新承重量，同一次编辑写进消费它的那篇笔记的 INDEX 行「依据」列（不另立账本）。

本条可被覆盖，写明理由即可。
